# NexaLayer for AI Agents

NexaLayer is a managed network Session layer for AI agents and browser automation. The **default production model is route-A: human-funded, agent spends within budget guardrails**. An owner funds the account and sets Key / daily limits; the agent discovers current products and prices, creates a bounded Session, reads health and usage, rotates when needed, and cleans up through an API or MCP server.

## Install in one command

```bash
npx -y @nexalayer/mcp
```

Set `NEXALAYER_API_KEY`, then connect the command as a stdio MCP server. [Request an API key and one-time trial credit](https://nexalayer.net/agents?source=agents-docs) (no card required for the trial).

## Safe agent flow (route-A)

1. Call `nexalayer_list_products` to read a current price.
2. Call `nexalayer_get_budget` to verify the spend boundary.
3. Ask the owner to approve the quoted purchase when policy requires it.
4. Call `nexalayer_create_session` with a unique idempotency key.
5. Monitor health and usage; rotate only when indicated.
6. Clean up the Session when the task finishes.

Discovery and health calls are read-only. Creating a Session can spend money, and changing a budget changes policy; keep human approval enabled for both. Prices come from the live products API — do not hard-code them in prompts or scripts.

## Funding model

- **Default (route-A):** the owner tops up (for example USDT TRC20 recharge through the API) and configures spend limits; the agent operates only inside those limits.
- **Optional track:** [x402 as an optional payment path](/en/x402-evaluation) is documented separately for teams that want agent-native HTTP `402` settlement later. It is not the default onboarding or MCP path, and it is not required to use NexaLayer Sessions.
